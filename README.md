# РядТерра

**Прогноз расходов и кандидаты структурных изменений. Задача №2 СберИндекса.**

Автор: **Сенюшин Дмитрий Иванович**.

Репозиторий: [DmitriiS-sber/ryadterra-sberindex](https://github.com/DmitriiS-sber/ryadterra-sberindex).
Научная версия — 05.10.2026; подготовка публикации — 06.10.2026.

Главный результат: исторические результаты воспроизведены в предыдущей проверке, но преимущество на новых данных и раннее обнаружение реальных экономических шоков пока не доказаны. **108 первых сигналов в 54 территориях — кандидаты на изменения.** Независимой разметки их экономических причин нет.

## Начать работу

Linux или WSL2, Python 3.12. Все команды выполняются из корня репозитория.

```bash
git clone https://github.com/DmitriiS-sber/ryadterra-sberindex.git
cd ryadterra-sberindex
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-checks.txt
make check-source
```

`check-source` проверяет синтаксис и выполняет девять существующих регрессионных проверок выбора пересмотров и доступности данных на дату отсечения. Для него не нужны данные, PyArrow, Prophet, веса моделей или API-ключи. Это проверка кода протокола, а не точности прогноза.

Для короткого расчёта установите аналитические зависимости. Затем распакуйте полный `SberIndex_Task2_Project.zip` из присланного выпуска и скопируйте его папку `data/processed/` в этот проект либо получите данные командой `python src/prepare.py` с первоисточников:

```bash
python -m pip install -r requirements-core.txt
make smoke-lite
```

`smoke-lite` сравнивает последнее значение и затухающий тренд на первых восьми территориях, одной дате отсечения и горизонтах 1/3/6/12. Выходные файлы находятся в `results/smoke-lite/`; сохранённые конкурсные метрики не заменяются. После копирования подготовленных данных доступ к первоисточникам и загрузка Chronos для этого запуска не требуются. Таблицы расходов и прогнозы отдельных территорий в GitHub не публикуются.

Полный набор зависимостей, запуск восьми основных моделей и отдельного Prophet по умолчанию, детекторов и диагностики: [инструкция запуска](docs/RUN.md). Полная валидация по сохранённым прогнозам требует полного комплекта `SberIndex_Task2_Project.zip` из исходного архива; тяжёлые прогнозные траектории в этот репозиторий не включены.

## Результаты и границы интерпретации

Цель — оценка средних номинальных месячных безналичных расходов жителей территории, в рублях. История: январь 2023 — декабрь 2024. Исходные данные содержат 303 126 строк, 2 190 ID и шесть категорий. Для «Все категории» отобраны 2 075 территорий с полным 2023 годом; 575 пропусков 2024 сохранены. Названия территорий и соответствие ОКТМО не подтверждены.

MAE, округлённая до рубля, по доступным тестовым парам из [сохранённой таблицы](results/validation/forecast_by_horizon.csv):

| Модель | 1 месяц | 3 месяца | 6 месяцев | 12 месяцев |
|---|---:|---:|---:|---:|
| Prophet, выбранная конфигурация | 1 884 | 2 262 | 2 758 | 2 904 |
| Последнее значение | 2 620 | 2 859 | 2 962 | 4 701 |
| Затухающий тренд | 2 744 | 3 736 | 3 234 | 1 734 |

Модель выбиралась по 2024 году, поэтому эти оценки ретроспективные. Для горизонта 12 месяцев доступна одна дата проверки. Высокий общий R² во многом связан с различиями между территориями; он не доказывает точность изменений во времени. Прогнозные интервалы не валидированы. Chronos-Bolt выпущен позже всех дат отсечения и рассматривается как современный ретроспективный benchmark.

CUSUM, Page–Hinkley, EWMA и Shewhart калибруются и проверяются на раздельных искусственных рядах. Синтетическая частота ложных тревог не измеряет precision/recall по реальным экономическим шокам. Проверка ранних предупреждений использует отдельно обозначенный proxy; 17 сообщений Банка России являются 17 независимыми публикациями. Доказанного улучшения от новостей нет.

## Воспроизводимость и следующие этапы

[Проверки публикации](docs/CHECKS_20261006.md) отделяют выполненные здесь действия от результатов предыдущего аудита. Закреплённые научные исходники и их SHA-256 в `configs/prospective_lock.json` сохранены. Чистая установка всего аналитического окружения и повторное обучение Chronos здесь не подтверждены; ограничения PyArrow и доступа к пакетам описаны в документации.

[Статус проекта](docs/STATUS.md) фиксирует этапы: GitHub → публичный сайт → проверка опубликованного сайта и материалов. Для будущего независимого теста нужны новые наблюдения с датами публикаций и версиями, заранее зарегистрированные цели и независимая разметка событий. Непроверенные прогнозы из истории до декабря 2024 не являются актуальным прогнозом на октябрь 2026. Конкурсная заявка не отправлена.
