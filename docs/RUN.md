# Обновление по валидации, 4 октября 2026

Для пересчёта исправленного протокола используйте [VALIDATION_RUN.md](VALIDATION_RUN.md) и `make validation`. Полный исходный расчёт ниже сохраняет историческую схему forecast. Детекторы запускайте с `--config configs/validation.yaml`; добавленные диагностика и news_detector обязательны для текущего отчёта.

# Инструкция по запуску

Все команды выполняются **из корня проекта**, где находятся `README.md` и
`requirements.txt`. Проверенный вариант — Linux и Python 3.12 на CPU.
Windows: используйте WSL2 и те же команды.

## 1. Получить файлы

Публичный репозиторий: https://github.com/DmitriiS-sber/ryadterra-sberindex.

```bash
git clone https://github.com/DmitriiS-sber/ryadterra-sberindex.git
cd ryadterra-sberindex
```

В репозитории есть код, конфигурации, русская методология и агрегированные
таблицы метрик. Таблицы расходов и прогнозы отдельных территорий не включены.
Для `make smoke-lite` после установки зависимостей скопируйте `data/processed/`
из полного комплекта либо получите данные с первоисточников через `prepare.py`.
Для проверки только кода и as-of протокола данные не нужны: `make check-source`.

Полный комплект `SberIndex_Task2_Project.zip` из присланного архива дополнительно
содержит сырую выгрузку, реестр, сохранённые прогнозы/траектории и PDF/PPTX.
Для `make validation` распакуйте его отдельно в `sberindex_task2` и следуйте
этой инструкции и `VALIDATION_RUN.md`. Эти тяжёлые файлы не включены в GitHub.
Документы релиза от 05.10.2026 описывают состояние до публикации репозитория;
текущий статус указан в `docs/STATUS.md`.

## 2. Установить окружение

```bash
python3.12 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

Версии прямых зависимостей закреплены в `requirements.txt`. Фактические версии
основного расчёта записаны в `results/main/run_manifest.json`. GPU, платные
сервисы и API-ключи для исследования не нужны. Требуется несколько гигабайт
места для Python, PyTorch и весов модели; точное время установки зависит от сети.

Для короткого запуска **без фундаментальной модели** вместо полного набора:

```bash
python -m pip install -r requirements-core.txt
```

Этот набор поддерживает численные расчёты без Chronos и сборку PDF. Он не
воспроизводит сравнение с Chronos; зависимости и веса Chronos нужны отдельно.

## 3. Данные: готовый комплект или получение с первоисточников

Если распакован полный комплект, для короткой проверки и пересчёта прогнозов
сеть не нужна. Уже есть `data/processed/panel.parquet` и новостные признаки.
Chronos использует сеть при первой загрузке весов, если их ещё нет в кэше.

Готовая панель и новостные признаки находятся в полном комплекте. После их
копирования для проверки установки на небольшом наборе простых моделей
выполните `make smoke-lite`. Это проверка исполнения, а не новая оценка
конкурсного качества.

Для восстановления данных из архива исходников:

```bash
python src/prepare.py
```

Скрипт загружает архив СберИндекса и сообщения Банка России, проверяет SHA-256
закреплённого архива, создаёт месячную панель и признаки. Если первичные сайты
недоступны, этот этап завершится ошибкой; используйте полный комплект с уже
подготовленными данными. Публичные тексты новостей и веса Chronos не включены
в распространяемый комплект.

## 4. Короткий запуск

Полный набор восьми основных моделей на первых восьми территориях:

```bash
python src/forecast.py --limit 8 --workers 2
```

После сокращённой установки:

```bash
python src/forecast.py --limit 8 --workers 2 --skip-chronos
```

Выход: `results/smoke/metrics.csv`, `predictions.parquet`,
`forecast_paths.parquet`, `run_manifest.json`, `model_errors.json`.
Основные конкурсные расчёты не перезаписываются. Это проверка исполнения,
а не репрезентативная оценка качества на всех муниципалитетах.

## 5. Повторить весь аналитический расчёт

На подготовленных данных, с полной установкой зависимостей:

```bash
python src/forecast.py
python src/default_baseline.py
python src/detect.py --config configs/validation.yaml
python src/news_warning.py
python src/future_warning.py
python src/forecast.py --availability-lag 1
python src/predict.py
python src/validation_diagnostics.py
python src/news_detector.py
python src/verify_validation.py
python src/verify.py
python src/build_materials.py
```

Порядок важен: дополнительный Prophet и предупреждения используют результаты
основного расчёта. Команды без `--output-dir` заменяют соответствующие файлы в
`results/`. `make all` дополнительно запускает `prepare.py` первым шагом и
потребует доступа к первоисточникам либо локальных исходных кэшей.

`build_materials.py` создаёт отчёт, графики и данные презентации. Готовые PDF и
PPTX презентации включены в полный комплект; генератор PPTX не входит в
аналитическую последовательность. Не следует утверждать, что `make all`
заново создаёт PPTX.

## 6. Настроить гиперпараметры

Сохраните исходный конфиг и выполните эксперимент отдельно:

```bash
cp configs/experiment.yaml configs/my_experiment.yaml
# Измените параметры в configs/my_experiment.yaml.
python src/forecast.py --config configs/my_experiment.yaml --output-dir results/my_experiment
python src/detect.py --config configs/my_experiment.yaml --output-dir results/my_detection
```

Назначение параметров и границы настройки: `docs/CONFIGURATION.md`.
`configs/smoke.yaml` — готовый пример с двумя простыми моделями и одной датой;
его можно запустить с `--limit 8` и отдельной папкой результатов.
`--config` у `forecast.py`, `detect.py` и `predict.py` выбирает YAML; остальные
аналитические команды используют `configs/experiment.yaml` и фиксированные
конкурсные папки. Пользовательский запуск не обновляет автоматически отчёт
или результаты предупреждений.

## 7. Проверить сохранённые результаты

В полном комплекте:

```bash
python src/validation_diagnostics.py
python src/news_detector.py
python src/verify_validation.py
python src/verify.py
```

Проверка пересчитывает MAE, проверяет общий набор тестовых целей, отсутствие
использования будущих новостей и наблюдений, отбор территорий по 2023 году,
матрицы ошибок предупреждений и другие численные условия. На ошибке команда
завершается ненулевым кодом; успешный итог сохраняется в
`results/verification.json`. Это проверка исследовательских расчётов,
а не независимое подтверждение экономических причин сигналов.

## 8. Получить прогноз на обновлённой панели

```bash
python src/predict.py --input data/processed/panel.parquet --origin 2024-12 --model prophet_auto --output results/my_forecast.csv
```

Вход: Parquet, индекс `territory_id`, столбцы последовательных месяцев
`YYYY-MM`, положительные расходы в рублях или NaN. На дату отсечения требуется
как минимум 12 месяцев; первое наблюдение должно быть заполнено. Пропуски
в истории заполняются только предыдущими значениями.

Модели: `prophet_auto`, `damped_trend`, `chronos_bolt_tiny`.
В CSV: территория, дата отсечения, горизонт, целевой месяц, модель и прогноз;
для Chronos дополнительно q10/q90 без доказанного покрытия интервалов.
Исходная выгрузка заканчивается декабрём 2024: прогнозы из неё относятся к
2025 году и не являются актуальным прогнозом на 2026 год.
