# Устройство исходного кода

| Файл | Назначение | Основной результат |
|---|---|---|
| `src/config.py` | Загрузка и базовая валидация настроек, выбор ревизии Chronos | Исполняемый конфиг |
| `src/prepare.py` | Загрузка первичных источников, аудит и подготовка данных | Месячная панель и новости |
| `src/forecast.py` | Историческое сравнение 8 моделей, одинаковые тестовые пары, MAE и дополнительные метрики | `results/main/` либо выбранная папка |
| `src/default_baseline.py` | Дополнительный Prophet с настройками по умолчанию | Сравнение 9 конфигураций |
| `src/detect.py` | CUSUM, Page–Hinkley, EWMA и Shewhart: раздельная калибровка/проверка на искусственных рядах и сигналы по реальным расходам | `results/detection/` |
| `src/news_warning.py` | Словарное предупреждение о повышении ставки в следующие 90 дней | Метрики новостного модуля |
| `src/future_warning.py` | Проверка предупреждения об устойчивом изменении расходов в будущем трёхмесячном окне | Матрицы ошибок, precision/recall/F1 |
| `src/predict.py` | Прогноз по панели до выбранного месяца | CSV прогнозов |
| `src/verify.py` | Численные проверки метрик и отсутствия использования будущей информации | JSON проверки |
| `src/build_materials.py` | Отчёт PDF, графики и данные слайдов из расчётов | Методологические материалы |
| `src/package.py` | Упаковка и контроль целостности финального комплекта | ZIP и манифест SHA-256 |

## Архитектура

1. СберИндекс и первичные сообщения Банка России поступают в `prepare.py`.
2. Подготовленная панель и признаки по дате публикации поступают в прогнозы.
3. На каждой дате отсечения модели видят только доступную историю; будущие
   новости в рекурсивном прогнозе не подставляются.
4. Прогнозы сравниваются на общих доступных целях. Последовательные детекторы
   используют полученные наблюдения; предупреждения оцениваются отдельно.
5. Сохранённые прогнозы и метрики поступают в проверку, отчёт и презентацию.

## Что означают выходные файлы

- `predictions.parquet`: пары «территория — дата отсечения — горизонт — модель»,
  прогноз и фактическая цель; основа MAE.
- `forecast_paths.parquet`: полные прогнозные траектории между датой отсечения
  и концом доступного тестового окна; основа предупреждений.
- `metrics.csv`: MAE в рублях, RMSE, R², абсолютные процентные ошибки по разрезам.
- `model_errors.json`: ошибки отдельных моделей. Новый запуск после сохранения
  журнала завершается с ошибкой, если хотя бы одна модель не рассчиталась.
- `run_manifest.json`: хеш настроек и протокола, модели, версии библиотек,
  время вычислений, число ошибок и фактически использованные параметры.

Исследование не содержит торговых рекомендаций, доказанной причинной модели
или разметки реальных структурных шоков. Идентификаторы территорий сохраняются
как в источнике: соответствие названиям муниципалитетов не выдумывается.

## Модули исправлений

| Файл | Назначение |
|---|---|
| validation_diagnostics.py | Метрики по датам/территориям, равные территориальные веса, WAPE, MASE, within R², условный bootstrap, стресс-сценарии |
| asof.py | Панель из реально доступных публикаций и версий, запрет неизвестных дат |
| prospective.py | Фиксация кода, регистрация будущих тестовых ключей, однократная оценка полного теста |
| evaluate_events.py | Направление, сопоставление один к одному, окно и цензурирование независимых событий |
| news_detector.py | Парная абляция остаточных детекторов с/без новостей |
| recheck_sources.py | Повторная проверка текущих первичных страниц и хешей без включения полных текстов |
| verify_validation.py | Регрессионные проверки научно значимых исправлений |
| build_validation_materials.py | Обновлённый отчёт, графики и данные презентации |
